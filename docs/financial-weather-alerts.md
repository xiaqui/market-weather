# 金融気象警報・金融地震 構想

## 位置づけ

Market Weather を単なる「上がる / 下がる予報」ではなく、金融市場を天気・警報・地震として読むアプリへ拡張するための構想メモ。

現時点では主にUI / 概念設計であり、以下の警報ロジックは未実装。既存の金融天気図（Cross-Asset Historical Analog）と組み合わせ、単純な固定条件だけでなく「過去の似た金融天気図で何が起きたか」を使って警報・注意報の発生確率や説明を作る方向を想定する。

## 1. 基本世界観

- 通常の値動き・トレンド → 晴れ / 曇り / 雨
- 徐々に悪化する市場環境 → 注意報 / 警報 / 台風的イベント
- 突然の大規模ショック → 金融地震
- ショック後の二次波及 → 金融津波

リーマンショックやコロナショックのような急激で広範囲な市場急変は、通常の悪天候ではなく金融地震として扱う。その後に遅れて広がる信用収縮・流動性低下・連鎖売りなどは金融津波として扱う。

## 2. 金融気象情報

気象アプリの警報カードに近い形で、現在の市場環境に応じた「金融気象情報」を表示する。

候補:

- 円安急進注意報
- 円高強風注意報
- 株安連鎖注意報
- 株式高温注意報
- リスクオフ警報
- 安全資産集中注意報
- 金逃避警報
- ボラティリティ雷注意報
- 市場分裂注意報
- 休場明けギャップ注意報
- 為替介入警戒

特に「為替介入」は、実際の政府・中央銀行による介入発生を断定的に予測するのではなく、円安 / 円高の急進、短期ボラティリティ上昇、USDJPYの伸びすぎ、他市場との乖離、過去の介入前後に似た金融天気図などから、為替介入警戒局面として表示する方が適切。

## 3. トリプル安注意報

「トリプル安」は一般に株・債券・通貨の同時安を指すため、現在の4市場（日経平均 / NYダウ / USDJPY / GOLD）だけでは厳密な意味のトリプル安を完全には表現できない。

将来的に日本国債・米国債・金利指標などを追加すると、本来の意味に近い「トリプル安注意報」を作れる。それまでは「株安連鎖注意報」「リスクオフ警報」等を先行実装する方が自然。

## 4. 警報は固定条件だけでなく金融天気図から作る

警報を単なるif文だけで決めるのではなく、金融天気図の過去類似局面を使う。

例として、現在が日経↓ / Dow↓ / USDJPY↓ / Gold↑ / ボラティリティ上昇で、過去の類似30局面のうち翌営業日に3市場以上が悪化した割合が67%なら、「株安連鎖注意報 発生可能性67%」のような出力につなげる。

つまり、警報そのものもCross-Asset Historical Analogの説明可能な出力にする。

## 5. 金融地震

突発的・広範囲・異常な市場急変を「金融地震」として扱う。

UI例:

- 金融地震速報
- 震源: 信用市場
- マグニチュード: M8.1
- 最大震度: 6強
- 広い市場で強い価格変動を観測
- 株式・為替・金利市場で急変に注意

金融地震は実際の地震尺度をそのまま流用するのではなく、金融市場向けの相対的な独自尺度として定義する。

## 6. マグニチュード

マグニチュード = ショック全体の規模。

候補材料:

- 複数市場の異常変動量
- 日次リターンの標準偏差倍率
- ボラティリティ急上昇
- 複数市場の同時急落 / 急騰
- 通常相関からの崩れ
- 市場間の同期性
- 過去平均との差
- 異常値の持続時間

マグニチュードは「どこでどれだけ揺れたか」ではなく、イベント全体のエネルギー / 規模という位置づけ。

## 7. 震度

震度 = 各市場で実際にどれだけ強く揺れたか。

同じ金融地震でも市場ごとに影響は異なる。

例:

- 日経平均 震度6弱
- NYダウ 震度5強
- USDJPY 震度4
- GOLD 震度5弱

候補材料:

- 対象市場の日次 / 数日リターン
- 平常時ボラティリティに対する異常度
- ギャップ
- intraday range（将来データ取得可能なら）
- ボラティリティ急上昇
- 過去分布におけるpercentile

重要なのは、Magnitude = 市場全体のショック規模、震度 = その市場での体感的な揺れ、と分けること。

## 8. 金融津波

地震 = 初動ショック、津波 = その後の二次波及、として扱う。

候補となる現象:

- 信用収縮
- 資金繰り悪化
- 追証売り
- 流動性低下
- 連鎖的ポジション解消
- 他市場への波及
- 数日遅れの株安 / 通貨急変
- 安全資産への集中

UI候補:

- 金融津波注意報: 市場間波及の可能性があります
- 金融津波警報: 複数市場への連鎖が進行しています
- 金融大津波警報: 信用・流動性危機レベルの波及に警戒
- 金融津波の心配はありません

## 9. 休場明けギャップと「蓄積した外圧」

既存の金融天気図では、休場中の市場について単に価格を停止扱いせず、最後の確定足からの経過時間と、その間の他市場累積変動を特徴として持つ。

これは「休場明けギャップ注意報」と相性が良い。市場が休んでいる間に海外市場が大きく動いた場合、その市場は止まっているのではなく、再開時に反映される可能性のある外圧が蓄積していると考える。

UI候補: 「休場中に海外市場の変動が蓄積しています。次回取引開始時の急変に注意してください。」

## 10. UIイメージ

一般的な天気アプリのように、上部に現在の金融天気を表示し、その下に警報カードを置く。

例:

- 現在の金融天気: 曇り時々雨
- 円安急進注意報とその他2件
- 警戒中: 円安急進注意報 / 株安連鎖注意報 / 休場明けギャップ注意報
- 金融市場は不安定です。今後1営業日、円安圧力が続く可能性があります。

金融地震発生時は通常警報とは別に、より強いカードを表示する。

## 11. 既存金融天気図との役割分担

- Trend / Analog / Ensemble = 翌営業日の方向予報
- 金融気象警報 = 特定の市場状態・連鎖リスクの警戒情報
- 金融地震 = 突発的な異常変動の検知
- 金融津波 = 初動ショック後の市場間波及リスク

将来的には、金融天気図の過去類似局面を共通基盤としてこれらをつなげる。

## 12. 実装時の原則

- 最初から多数の警報を実装しない
- まず説明しやすい2〜4種類から始める
- 固定しきい値だけに依存しすぎない
- 過去類似局面の実績を使えるものは使う
- 発生確率 / サンプル数 / 類似度を保持する
- 実際の政府介入・危機発生を断定しない
- 「注意報」「警戒」は予測モデル上の状態であることを明確にする
- 金融地震のMagnitude / 震度は独自尺度として定義する
- 金融津波は初動と二次波及を分離して評価する
- UI上の面白さだけでなく数値的に検証可能な指標にする
- 過去成績を見てから都合よく閾値を最適化しない

第一段階:

第二段階:

9. 金融地震速報

トリプル安については、債券 / 金利データ追加後に正式対応するのが望ましい。

## 14. この構想の核

Market Weatherの特徴は、単に金融用語を天気用語へ置き換えることではない。

- 複数市場の配置を見る
- 過去の類似局面を探す
- 休場中の外圧を蓄積として扱う
- 徐々に悪化する状態と突発ショックを分ける
- 初動ショックと二次波及を分ける
- それらを天気 / 警報 / 地震 / 津波として一貫したUIで見せる

最終的には「金融市場を数字の羅列ではなく、現在の天気と災害情報として直感的に読む」ことを目指す。
