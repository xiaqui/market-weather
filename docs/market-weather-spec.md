# 金融天気予報アプリ v0.1 開発指示書

## 0. プロジェクトの目的

日経平均、NYダウ、ドル円、金価格について、一般的な株価予想アプリではなく「天気予報」のような見せ方で翌営業日の相場を予報するAndroidアプリを作る。

重要なのは「明日の終値を一点で当てる」ことではない。

以下を予報する。

- 上昇／下落の確率
- 翌営業日の予想変動レンジ
- 相場の荒れやすさ
- 予報の信頼度
- 天気アイコンによる直感的表示

これは投資助言アプリではなく、過去データを用いた統計的な市場予報・実験アプリとして設計する。

## 1. 仮称

アプリ名：相場天気  
英字名：MARKET WEATHER  
package名（仮）：`jp.xiaqui.marketweather`

## 2. 対象市場

初期版では以下4つを表示する。

1. 日経平均
2. NYダウ
3. USD/JPY
4. GOLD

内部では `MarketId` 等のenumで管理し、後からS&P500、NASDAQ、BTCなどを簡単に追加できる構造にする。

## 3. メイン画面

縦画面スマートフォンを基本とする。

上部：

- MARKET WEATHER
- 本日の金融天気予報
- 最終更新日時

その下に4枚のカードを縦に並べる。

例：

```text
──────────────────
日経平均
☀

上昇確率　67%

予想レンジ
41,850 ～ 42,620

予想変動率
-0.6% ～ +1.2%

信頼度
★★★★☆

市場気圧
やや強い
──────────────────
```

同様に NY DOW / USD / JPY / GOLD を表示する。

## 4. 天気表現

- ☀️ 晴れ：上昇確率 65%以上
- 🌤 晴れ時々曇り：55%以上65%未満
- ☁️ 曇り：45%以上55%未満
- 🌧 雨：35%以上45%未満
- ⛈ 荒天：35%未満、または急変リスクが非常に高い

ただし、「方向感」と「荒れやすさ」は別概念として内部データを分離する。

たとえば上昇確率70%でもボラティリティが非常に高い場合は、晴れ表示に加えて「急変注意」を出せる構造にする。

## 5. 予報期間

v0.1では翌営業日のみ。

将来的に以下を追加予定。

- 今日
- 翌営業日
- 3営業日
- 1週間

モデル内部では `horizon = 1` のように拡張可能にする。

## 6. 初期予測アルゴリズム

最初からニューラルネットワークやLLMは使わない。

まず説明可能でバックテスト可能なモデルを作る。

主要特徴量：

- 1日 / 2日 / 5日 / 10日 / 20日騰落率
- 5日 / 20日 / 60日移動平均乖離率
- RSI 14
- MACD
- 過去5日 / 20日ボラティリティ
- 高値安値レンジ
- 前日の陽線／陰線
- 連続上昇日数
- 連続下落日数

市場間特徴量も使う。

たとえば日経平均予報には、前日のNYダウ、USD/JPY、金なども入力する。4市場を完全に独立させない。

## 7. 初期モデル

以下の複数モデルを用意する。

- Logistic Regression
- Gradient Boosting系モデル
- 単純トレンドモデル

各モデルから翌日上昇確率を取得し、最終値はアンサンブルする。

単純平均から開始してよい。後からモデルごとの重み付けを可能にする。

## 8. 信頼度

信頼度は上昇確率そのものではない。

複数モデルの予想がどれだけ一致しているかを利用する。

例：

- A 72%
- B 70%
- C 74%

→ 信頼度高

一方、

- A 78%
- B 44%
- C 51%

→ 信頼度低

v0.1ではモデル間の分散を主体に計算してよい。

## 9. 予想レンジ

翌営業日の終値そのものを一点予測しない。

現在値と過去ボラティリティから予想下限・予想上限を求める。

予測方向と過去の値動きを利用して、上下非対称レンジにしてよい。

## 10. 市場急変警戒

以下の条件等から内部状態を作る。

- CALM
- NORMAL
- CAUTION
- STORM

判定材料：

- 過去20日ボラティリティ
- 直近5日ボラティリティ
- 前日の値幅
- 市場間の異常変動

UIでは「安定 / 通常 / 注意 / 荒天」程度の表現にする。

## 11. データ構造

アプリ側で予測処理そのものを複雑にしない。

Python側で予報結果をJSON生成する。

例：

```json
{
  "generated_at": "2026-09-19T09:00:00+09:00",
  "markets": [
    {
      "id": "nikkei",
      "name": "日経平均",
      "current": 42000.0,
      "up_probability": 0.67,
      "range_low": 41790.0,
      "range_high": 42462.0,
      "confidence": 0.82,
      "weather": "sunny",
      "risk": "normal"
    }
  ]
}
```

Android側はこのJSONを読み込んで表示する。予測ロジックとUIを完全に分離する。

## 15. デザイン

金融アプリ特有の黒地＋チャートだらけにはしない。あくまで「天気アプリ」。

- 明るい背景
- 大きな天気マーク
- 市場名
- 上昇確率を大きく表示
- 数字は読みやすく
- 赤と緑だけに依存しない

一画面を見れば、今日は株高予報なのか、円高予報なのか、荒れそうなのかが5秒以内に理解できるUIにする。

## 16. 詳細画面

v0.1ではカードをタップすると最低限の詳細を表示する。

- 現在値
- 上昇確率
- 下落確率
- 予想レンジ
- ボラティリティ
- 信頼度
- モデル別予測

「AIが言ったから」ではなく予測根拠を多少確認できるようにする。

## 17. バックテスト

このアプリで最重要。

未来データ混入を絶対に起こさない。

各日について、その日までに利用可能だったデータだけで翌日を予測し、翌日の実績と比較する。

最低限保存する統計：

- 方向正解率
- Brier Score
- 予測確率のCalibration
- 平均予想レンジ
- 実際の価格がレンジ内に入った割合

特にCalibrationを重視する。

「上昇確率70%」と予報したケースを集めたとき、本当に約70%上昇しているかを確認する。単純な正解率だけでモデルを評価しない。

## 18. GitHub Actions

GitHubへのpushまたは手動実行でAPKを生成する。

workflow名：

`build-apk.yml`

処理：

checkout → Pythonセットアップ → Python依存パッケージインストール → 市場データ取得 → モデル生成／予測 → forecast.json生成 → JDKセットアップ → Gradleセットアップ → `./gradlew assembleDebug` → APKをArtifactとして保存

Gradleは必ずGradle Wrapperを使用する。

## 19. GitHub Actions完成条件

Actions画面から `Run workflow` を押す。

処理成功後、Artifactsから `market-weather-debug.apk` を取得できること。

ローカルAndroid StudioでビルドしないとAPKが作れない構成にはしない。GitHubだけでビルド可能にする。

## 20. データ取得失敗への対応

外部データ取得に失敗しただけでAndroidビルド自体が永久にできなくなる設計は禁止。

前回 `forecast.json` が存在する場合は、

取得失敗 → 警告 → 既存JSONを使用してAPKビルド

とする。

完全に `forecast.json` が存在しない場合のみビルド失敗としてよい。

## 21. API構造

市場データ取得処理は必ずDataProviderとして分離する。

特定サービスのURLをアプリ全体に直書きしない。

将来的に Yahoo系 / Stooq / 有料API / 自前サーバ等へ切り替えられる構造にする。

## 22. APIキー

秘密鍵をGitHubリポジトリへ直接コミットしない。

必要な場合はGitHub Actions Secretsを使用する。

APK内部にAPIキーを埋め込む方式は最終構成として採用しない。

## 23. オフライン動作

一度生成されたAPKは、最低限「最後に生成された予報」をオフライン表示できること。

つまり `forecast.json` はAPK内assetsにも保持する。

## 24. 更新ボタン

v0.1では「最新情報取得」ボタンはまだ不要。

APK生成時のデータを表示する。

画面には必ず予報生成日時を表示し、古い予報を今日の予報に見せない。

## 29. 最初の完成形

アプリを起動すると即座に、

- 日経平均
- NYダウ
- ドル円
- 金

の4枚の天気予報カードが表示される。

各カードには、

- 天気
- 上昇確率
- 予想レンジ
- 信頼度
- 荒天警戒

がある。

GitHub Actionsを手動実行すると、

最新市場データ取得 → 予測 → APK生成

まで自動実行される。
